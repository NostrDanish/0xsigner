# Security Audit — 0xsigner — 2026-10-20

## Summary

0xsigner is a browser-based "API proxy worker" generator: a Vite/React (MKStack-derived) app that collects a user's Cloudflare API token **in-browser only**, renders a hardened single-module Worker from a zod-validated non-secret manifest, and deploys it via the Cloudflare REST API (secrets pushed straight to the Worker secret store). It also embeds a standard Nostr login stack (@nostrify/react: nsec / NIP-46 bunker / NIP-07 / nostrconnect). Overall engineering quality is high: CORS allowlist-reflection, per-route rate limits, SSRF guards, body caps, upstream error sanitization, and a strict "manifest never contains secret values" contract. The most important issue is that the advertised `nip98` public-auth mode is not implemented anywhere in the generated runtime, so selecting it yields **no authentication at all**.

Findings: 0 Critical / 1 High / 3 Medium / 2 Low

## Findings

| ID | Severity | File/Area | Issue | Recommended fix |
|----|----------|-----------|-------|-----------------|
| SIG-01 | HIGH | `src/lib/signer/runtime/core.ts` `checkPublicAuth()` + `entry.ts` | `publicAuth: { type: 'nip98' }` returns `true` unconditionally ("presence-only here"), and no per-route NIP-98 verification exists in `providers.ts`/`entry.ts`. An operator who selects NIP-98 auth gets a completely unauthenticated gateway while the UI implies it is enforced — silent auth bypass by configuration. | Implement real NIP-98 verification (kind 27235, u/method/payload tags, created_at window, schnorr verify via a vendored verifier) in the generated runtime, or remove/disable the nip98 option until implemented and warn in the wizard. |
| SIG-02 | MEDIUM | `core.ts` `rateLimit()` | Rate limiting is an in-memory Map per isolate; Cloudflare isolates are ephemeral and multi-region, so limits are trivially evaded by reconnecting / geographic dispersion. Comment acknowledges this. Also `buckets.clear()` at >10k keys lets an attacker reset ALL buckets by flooding distinct identity keys. | Use a Durable Object or Workers rate-limiting binding; replace global `clear()` with oldest-entry eviction. |
| SIG-03 | MEDIUM | `core.ts` `checkTargetUrl()` | SSRF guard checks literal IPs/hostnames but not DNS resolution — a public hostname resolving to a private/link-local address (DNS rebinding) bypasses the guard for crawler/tor-gateway targets. | Resolve-and-pin where possible, or document the limitation; recommend `allowedDomains` allowlists for crawler template (currently defaults to empty = any public host). |
| SIG-04 | MEDIUM | Nostr login stack (`App.tsx` `NostrLoginProvider storageKey='nostr:login'`, `useLoginActions.ts`) | nsec logins via `NLogin.fromNsec` are persisted by @nostrify/react to `localStorage` under `nostr:login` — private keys at rest in web storage, exfiltratable by any XSS or malicious dependency. Common Nostr-client pattern but sensitive for a tool that also handles Cloudflare API tokens in the same origin. | Prefer NIP-07/NIP-46 logins in docs/UI; add a prominent warning on nsec login; consider sessionStorage-only persistence for nsec logins. |
| SIG-05 | LOW | `core.ts` `checkPublicAuth()` | API-key comparison uses `===` (non-constant-time). Timing exploitation is impractical over the internet but easy to fix. | Use a constant-time comparison (hash both sides with SHA-256, then compare). |
| SIG-06 | LOW | Repo hygiene | No SECURITY.md; `.mcp.json` pins `@latest` MCP servers (`npx -y ...@latest`) — supply-chain drift for anyone running the agent config. | Add SECURITY.md; pin MCP server versions. |

## Secrets Check

- Reviewed: `.mcp.json`, `package.json`, `.github/workflows/deploy.yml`, `.gitlab-ci.yml`, `src/lib/signer/*` (cloudflare.ts, manifest.ts, templates.ts, runtime/*), hooks.
- GitHub secret scanning unavailable (repo lacks Advanced Security); `search_code` returned incomplete indexing for this repo, so high-risk files were read directly instead.
- **No committed secrets found.** Cloudflare API tokens are designed to stay browser-side (never stored/logged); provider keys are pushed only to the Worker secret store via `putSecret` — the manifest carries binding NAMES only. This separation is correctly implemented in `manifest.ts` (`requiredSecrets`) and `cloudflare.ts`.
- Code search for `nsec1` / private-key literals: no hits (search index incomplete; manual review of key-handling files found none).

## Dependency Notes

- `package.json`: modern, pinned-with-caret deps; `esbuild-wasm` pinned exactly (0.28.2) — good since it runs in-browser to transpile generated workers. No git-URL or wildcard deps.
- Heavy UI dependency surface (radix, recharts, embla, etc.) increases XSS/supply-chain blast radius for an app handling API tokens + nsec keys (see SIG-04); keep `npm audit` / Dependabot enabled.
- `nostr-tools ^2.23.3`, `@nostrify/* ^0.55.x` — current lines, no known unpatched advisories flagged.

## Recommended Actions

1. [HIGH] Fix or remove the unimplemented `nip98` publicAuth mode before any deployment relies on it (SIG-01).
2. [MEDIUM] Replace per-isolate rate limiting with a durable mechanism; fix `buckets.clear()` reset vector (SIG-02).
3. [MEDIUM] Document/harden SSRF DNS-rebinding gap; ship crawler template with non-empty `allowedDomains` guidance (SIG-03).
4. [MEDIUM] Discourage nsec login (localStorage persistence); prefer NIP-07/46 in UI copy (SIG-04).
5. [LOW] Constant-time secret compare; add SECURITY.md; pin `.mcp.json` server versions (SIG-05, SIG-06).
