# Improvement Deep-Dive — 0xsigner — 2026-10-21

Scope: main. Sources read: `package.json`, `README.md`, full commit log, `src/lib/signer/runtime/providers.ts` (all 7 adapters + health checks), runtime/ directory listing, plus the sibling fork `NostrDanish/Leef-signer` (commit log + `runtime/` listing) to trace what the fork changed.

## Top recommendations (ranked, with effort S/M/L)

1. **Upstream the Leef-signer fork's runtime fixes; retire the fork's TS→JS approach (M).** The fork (Sep 16) hit the real bug — "CF does not transpile TypeScript on upload" — and fixed it by converting `runtime/{core,providers,entry}.ts` to plain JS, permanently stripping type checking from the most security-sensitive code (SSRF guard, secret handling, CORS). Upstream fixed the same root cause better on Sep 22 (`buildWorkerJs()` esbuild-wasm transpile in-browser + `generator.test.ts`). But the fork's *other* changes never came back:
   - CORS **wildcard-subdomain origins** (`https://*.example.com`) in core + manifest schema
   - **PROVIDER_TIMEOUT (504) vs PROVIDER_UNAVAILABLE (502)** distinction, and the **body-read abort race fix** (slow generation past the deadline surfaced as swallowed `{"ok":false}`)
   - openai adapter: configurable `timeoutMs`, `tokenParam` (max_tokens vs max_completion_tokens), `modelEnvName` (plain-text var override), `extraBody` (e.g. `provider.zdr`, `response_format`), `{task,message,data}` shorthand
   - `typesafe` provider adapter (judgment gateway)
   Action: cherry-pick these into the TS sources, then add a note in AGENTS.md/ARCHITECTURE.md: **the transpile step is the invariant; never convert runtime/ to .js to work around it.**
2. **Provider-adapter test suite before the next fork (M).** `generator.test.ts` only proves the bundle is valid JS. Add per-adapter tests (vitest + miniflare or plain Request/Response mocks):
   - secret-only-from-env invariant: adapters must never read credentials from `cfg` (static test scanning for `cfg.secretValue`-style access + runtime canary)
   - SSRF guard: private IPv4/IPv6, `169.254.169.254`, DNS-less IP literals, redirect-less enforcement
   - CORS: exact match, wildcard-subdomain match/non-match, no reflection of unknown origins
   - openai adapter: model allowlist cannot be bypassed, system prompt always wins over client `system` messages, `max_tokens` capped by operator
   - error paths: upstream 401/429/5xx map to client-safe messages and never leak upstream bodies
   - `PAYLOAD_TOO_LARGE` at exactly 256 KB boundary
   - Plus a CI smoke: generate worker → `wrangler deploy --dry-run` (or `wrangler dev` startup check) so the TS→JS upload break can never regress.
3. **CI gate (S).** `.github/workflows/deploy.yml` only deploys Pages. `npm test` already runs tsc + eslint + vitest + build — wire it as a PR/push gate, drop `--legacy-peer-deps` if used.
